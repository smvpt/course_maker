## Как заполнять

**claims — утверждения автора.** Не сжимай: каждая самостоятельная мысль автора из этих единиц — отдельное утверждение; числа, пороги, диапазоны и условия применимости — отдельными утверждениями. Плотный текст даёт много утверждений, это нормально.
- text — своими словами, одна фраза до 25 слов;
- kind — observation (наблюдение, факт, измерение), inference (вывод автора из наблюдений), assumption (допущение, при котором верен вывод);
- quote — ДОСЛОВНАЯ цитата из текста единицы выше, на которую опирается утверждение: скопируй подряд идущий кусок, 8–40 слов, без пересказа, без многоточий внутри, без исправлений; для формулы — кусок формулы как в тексте;
- page_pdf — страница единицы, откуда цитата;
- source_kind — text, formula, table, task, figure_caption или figure_description_model.

**layers** — слои объяснения: topic (тема, одна фраза), main (суть, 2–3 фразы, первая — главное), mechanism (как это работает и почему), practice (как это применяют на практике), nuances (условия, ограничения, исключения), deeper (ветки «глубже»: что почитать или куда копнуть, 0–3 пункта). Только то, что следует из текста; если чего-то в тексте нет — скажи об этом коротко, не выдумывай.

**links** — связи: prerequisite (target — slug узла плана, без которого не понять этот), example_of (этот узел — пример для узла target), refutes_misconception (target — id заблуждения из списка ниже), to_data (target — data.<что_за_данные>, например data.las_curve, если узел ведёт к работе с реальными данными). Для карточек-предпосылок target = prereq.<термин_латиницей>.

**misconception** — заблуждение, которое узел исправляет, если есть: ref — id из списка ниже или null, text — в чём заблуждение и как на самом деле.

**data_meaning** — «что это значит для данных»: from_chapter — только то, что прямо следует из главы (какие данные, что в них видно, что нельзя вывести); breaks — где это перестаёт работать; hypotheses — догадки сверх главы, каждая с hypothesis = true.

**it_analogy** — аналогия из ИТ/данных/ML и breaks_where — где именно она перестаёт работать (обязательно).

**now_practice** — если книга описывает устаревшую технику, приборы или программы: как это делают сейчас (пометь историческое). Иначе null.

**inefficiency_lens** — для процедурных узлов: входные данные, ручные шаги, точки суждения специалиста, время, типичные ошибки. Для непроцедурных — null.

**decision_on_data** — если узел учит принимать решение по данным: признаки, правило, вывод, контрпример. Иначе null.

**worked_examples** — ВСЕ разобранные примеры автора из этих единиц: условие, шаги решения, итог с числами автора (числа — только из текста). **book_tasks** — ВСЕ задачи книги из этих единиц: номер, формулировка, какой рисунок нужен (или null).

**terms_introduced** — термины, которые этот узел вводит и объясняет; **terms_used** — термины, которые узел использует, но не объясняет.

**needs_scan** — рисунки, без изображения которых узел не понять (их смысл держится на легенде или кривых): page и что именно нужно увидеть.

Поле by_model везде, где оно есть, ставь true: эти тексты пишешь ты.

Числа: в любых полях используй только числа, которые есть в тексте единиц. Не придумывай примеры с новыми числами.
