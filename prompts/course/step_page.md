## Что нужно сделать
Перепиши поля узла связными абзацами для новичка, который знает статистику и программирование, но не знает предметной области. Верни JSON `{"paragraphs": [...]}`.

У абзаца поля:
- `block`: к какому блоку страницы он относится.
- `text`: текст абзаца на русском.
- `claim_ids`: id утверждений узла (`claims[].id`), на которых держится абзац. Минимум один у КАЖДОГО абзаца без исключений, включая `main`, `why`, `practice`, `nuances`, `data` и `analogy`: пустой список — ошибка, шаг уйдёт в запасной вариант. Если абзац пересказывает поле узла без своего утверждения (например `why_here`), укажи ближайшее по смыслу утверждение узла. По ним курс ставит «стр. N», поэтому указывай только те утверждения, из которых реально взят текст абзаца.
- `terms`: термины из `terms_introduced` узла, которые вводятся в этом абзаце. В `text` каждый такой термин выделен как `[[термин]]`, ровно по одному разу на термин, и тут же объяснён простыми словами. Если термина нет, список пустой.
- `hypothesis`: `true`, если абзац передаёт гипотезу из `data_meaning.hypotheses`. Только в блоке `data`.
- `limit`: `true` у абзаца, который называет границу аналогии, то есть где она перестаёт работать. Только в блоке `analogy`.

## Блоки и откуда их брать
- `main` (суть): из `layers.main`. Строго 2–3 фразы, первая фраза говорит главное.
- `why`: из `why_here`.
- `how` («как это работает»): из `layers.mechanism` и утверждений узла. Передай все мысли автора из утверждений, формулы и таблицы не пересказывай, они показываются отдельно. Можно сослаться на формулу или таблицу словами и указать их claim_id. Блок `how` обязателен всегда, когда в узле есть хотя бы одно утверждение, которое не формула и не таблица, даже если `layers.mechanism` пуст: тогда перескажи в `how` это утверждение и не оставляй его только в `main`. Блоки `main` и `how` не должны повторять друг друга дословно: `main` даёт главное, `how` — подробности и условия.
- `practice`: из `layers.practice` и `now_practice`.
- `nuances`: из `layers.nuances`.
- `misconception` (частая ошибка): из `misconception`.
- `decision`: одна фраза о том, что показывает решение на данных (`decision_on_data`). Сами признаки, правило и вывод показываются отдельно.
- `data` («что это значит для данных»): из `data_meaning.from_chapter`, `breaks` и `hypotheses`.
- `analogy`: из `it_analogy`: один абзац с аналогией и один абзац с `limit=true` по `breaks_where`.
- `deeper`: из `layers.deeper`.

Блок пишешь только тогда, когда в узле для него есть непустой текст. Для пустого поля блока в ответе быть не должно.

## Жёсткие правила
1. Ничего сверх узла: ни фактов, ни примеров, ни чисел, ни терминов, которых в узле нет. Если сомневаешься, пропусти.
2. Числа только из узла и в том же виде. Новых чисел не вычисляй.
3. Каждая фраза не длиннее 20 слов. Длинную мысль режь на несколько фраз.
4. Термин при первом упоминании выделяй `[[...]]` и объясняй сразу, в том же абзаце. Объяснение бери из узла.
5. Пиши просто и по-человечески, без канцелярита. Не обращайся к читателю по имени и не хвали его.
6. То, что автор утверждает, и то, что ты вывел, не смешивай. Гипотезы только с `hypothesis=true`.
7. Не придумывай claim_id. Бери только из `claims[].id` узла.
