# Проект «Глава → курс» — общие правила для всех агентов

Конвейер: глава книги → учебный слой → маршрутизация форматов → демо-курс (шаги, задания, карточки, иллюстрации, видео).
Полное ТЗ: `docs/tz.md`. Роль конкретного участника: `docs/roles/P1.md` … `P4.md` — прочитай свою.
При сомнении в требовании читай ТЗ, а не придумывай.

**Главная цель кода:** на НЕЗНАКОМОЙ главе (в т.ч. на английском и из другого домена, например бурения) конвейер сам собирает курс с минимумом ручных правок. Решение, которое работает только на обучающих главах, бесполезно.

**Дедлайн:** 26.11 до 09:45 — тег `v1.0-freeze` в git (организаторы подтвердили: заморозка = тег). После 10:00 код, промпты и доменный пакет геологии НЕ меняются.

**Жюри само скачивает все репозитории и запускает их своим ключом API.** Значит:
- новая глава запускается БЕЗ правки файлов: `make all MD=<путь к md> [PDF=…] [ERRATA=…] [PREREQ=…] [DOMAIN=…]`. Язык (ru/en) определяется автоматически, страницы — из меток `<!-- page N -->`, id главы — из имени файла (нижний регистр, латиница, `[a-z0-9_.-]`). `config/chapters.yaml` — только для наших обучающих и контрольных глав, тестовые туда не вписываются;
- модель и провайдер меняются переменными `.env` (`LLM_MODEL`, ключ провайдера), без правки кода; инструкция — в `docs/run.md`;
- всё, что нужно жюри, описано в `docs/run.md` и работает с чистого клона.

Ключевые правила схем:
- `page_pdf` — номер из метки `<!-- page N -->` в выданном md; `quote` — дословно из md (при сверке не учитываются пробелы, переносы и регистр).

## 2. Интерфейсы между зонами (зафиксированы, менять нельзя)

**Форматы данных** — только модели из `contracts/models.py` (pydantic v2). Читаешь и пишешь через них: `Model.model_validate_json(...)`, `model_dump_json(indent=2)`. Свои дубли форматов не создавай.

**Если в контракте не хватает поля** — не меняй контракт и никого не спрашивай. Положи данные в поле `ext` нужной модели под ключом своего модуля: `node.ext["course"] = {...}`, `node.ext["video"] = {...}`, `node.ext["verify"] = {...}`. Ядро обязано сохранять `ext` без изменений. Человек (П1) потом может поднять поле в контракт.

**LLM** — только через `pipeline/llm.py` (пишет П1, интерфейс фиксирован):

```python
from pipeline.llm import complete_json, complete_text
obj = complete_json(prompt="course/step_page", vars={...}, schema=SomeModel,
                    tier="default" | "strong" | "vision", images=[path, ...] | None)
txt = complete_text(prompt="video/script_draft", vars={...}, tier="default")
```
- `prompt` — путь в `prompts/` без `.md`; переменные в файле промпта — `{{name}}`.
- Кэш по хэшу (промпт + переменные + модель) в `cache/llm/`. При `LLM_OFFLINE=1` промах кэша — ошибка (так жюри запускает без ключа).
- Модели, ключи, цены — в `config/llm.yaml` и `.env`. Каждый вызов пишет токены и деньги в `out/_metrics/llm_calls.jsonl`.
- Невалидный JSON → повтор с текстом ошибки (не больше 2 раз) → исключение.
- Пока `llm.py` не готов (первый час), пиши код против этого интерфейса и тестируй на моках.

**Точки входа модулей** (каждый владелец реализует свою; П1 вызывает их из `Makefile`):

```
python -m pipeline.ingest.run    --ch <id>                    # П1 → units.json
python -m pipeline.structure.run --ch <id>                    # П1 → layer.json, coverage.json
python -m pipeline.route.run     --ch <id>                    # П1 → routing.json
python -m pipeline.verify.run    --ch <id>                    # П2 → out/<id>/verify/report.json (+ код выхода ≠0 при критических)
python -m pipeline.verify.external --pkg <path> --out <path>  # П2 → ReviewOutput (review_output.schema.json) по ReviewPackage
python -m pipeline.illus.run     --ch <id>                    # П3 → out/<id>/illus/
python -m pipeline.course.build  --ch <id> [--node <node_id>] # П3 → out/<id>/course/
python -m pipeline.video.build   --ch <id> --node <node_id> [--format short|long] [--draft]  # П4
python -m pipeline.video.spec    --ch <id> --node <node_id>   # П4 → script.json + scene_spec.json, без рендера
python -m domain.build     --domain <name> --ch <id>    # П2 → domain/<name>/
python -m journal.cli add --ch <id> --min <n> --what "..."    # П2 → журнал правок + коммит
```
Все команды: вход — файлы, выход — файлы, идемпотентно, падают с понятной ошибкой при нехватке входа.

**Make** (корневой `Makefile` пишет П1 и делает `include mk/*.mk`; цели своего модуля каждый пишет в свой `mk/<модуль>.mk`):
```
make install | make test | make smoke | make all CH=<id> | make rebuild NODE=<id> | make check PKG=<path> | make video NODE=<id>
```

**Зависимости** — каждый в свой `requirements/<модуль>.txt` с точной версией. Корневой `requirements.txt` (П1) только включает их через `-r`.
**Манифест** — каждый в свой `manifest/<модуль>.md`: инструмент, версия, лицензия, уходят ли данные во внешний сервис.
**Тесты** — каждый в свой `tests/<модуль>/`, на своих `fixtures/<модуль>/`, без сети.

**Доменные знания** (термины, заблуждения, чек-лист физики, цвета пород, словарь ударений) — только в `domain/<домен>/` (П2). Остальные модули читают пакет через `pipeline.common.domain.load(domain)` (П1) и НЕ хардкодят ничего геологического в коде.

## 3. Правила работы агента

1. Пиши только в свою зону (таблица выше). Если кажется, что нужно изменить чужое, — используй `ext`, свой адаптер внутри своей папки или мок. Не меняй чужое и не останавливай работу из-за этого.
2. Никакого хардкода под конкретную главу, автора, страницу или домен в `pipeline/`. Всё, что зависит от главы, приходит из входных файлов, `config/` или доменного пакета.
3. Промпты — только файлами в `prompts/<модуль>/`, не строками в коде. Промпты пишутся на русском, работают и для английских глав (курс всегда на русском, цитаты — на языке оригинала).
4. Падай громко. Не глотай исключения, не подставляй молча заглушки, пустые строки, «TODO» или выдуманные данные в выход.
5. Ничего лишнего: без новых зависимостей без нужды, без абстракций «на будущее», без демо-скриптов, без новых README, без рефакторинга, о котором не просили. Минимальный код, который проходит тест.
6. Сначала тест, описывающий «готово», потом код.
7. Перед «готово»: `make test` (весь, не только свой) и `make smoke` зелёные. В ответе: список изменённых файлов (все — в твоей зоне), что проверено, что НЕ проверено.
8. Не трогай `.env`, `cache/`, `out/` руками, не удаляй файлы, которых не создавал. Не коммить ключи.
9. НИКОГДА не открывай и не читай `data/organizers/02_модуль_проверки/контрольный_пакет/key.json` (ключ самопроверки), пока человек явно не скажет «прогон сделан».
10. Коммиты маленькие, сообщение `[P<n>] что сделано`. В `main` мёржит П1.

## 4. Жёсткие требования ТЗ, которые не нарушает ни один модуль

- Учебный слой (`layer.json`) — единственный источник правды: курс, задания и ролики строятся из него, а не из текста книги.
- Номер страницы везде = страница PDF = метка `<!-- page N -->` в md (проверено: Барабошкин «Дельты» = 30, Баренблатт §4 = 38, как в ТЗ). Печатный номер, если нужен, — отдельное поле `page_printed`.
- У каждого утверждения — страница и дословная цитата. Каждое число в тексте курса и сценария есть в исходной единице главы.
- Кадры и иллюстрации классов A и B — только кодом из данных или расчёта. Генерации изображений или видео в A и B нет. Текст, цифры, оси и стрелки генеративная модель не рисует никогда.
- Курс открывается локально из файла, без сервера и логина; 390 px и 1280 px без горизонтальной прокрутки; светлая и тёмная тема; текст от 16 px; ≤ 30 МБ на главу без видео.
- Озвучка — edge-tts (онлайн-голоса Microsoft); наружу уходит только текст сценария.
- Главы и ролики никуда не публикуются (никаких открытых ссылок). Репозиторий приватный.
- Честность (обязательно): плашка «не в масштабе» с тем, ЧТО и ВО СКОЛЬКО преувеличено; хотя бы один кадр серии в истинном масштабе; наблюдение отделено от вывода («сигнал → вывод» видно); у каждого кадра метка происхождения; устаревшая техника помечена «исторический прибор» + «как сейчас».
- В тексте курса и сценария видно, что написал автор (цитата), а что модель; гипотезы помечены.
- Шортсы-крючки без своего узла — не больше 10–20% роликов.

## 5. Цель по баллам (чтобы помнить, что важно)
Допуск: пакет из 6 частей полный, курс открывается по инструкции, заморозка до теста, страницы у всех утверждений, ≤1 критической ошибки.
Баллы: обучение 40 (слой 15, курс 15, видео 10) · тест 45 (двойники 30, сдвиг 5, закладки 10) · процесс 15 (ручной труд 10 — ≤30 мин правок на главу, запуск и пересборка 5).
Вывод: 60 баллов из 100 — за то, что конвейер сам работает на незнакомой главе. Устойчивость важнее полировки.
