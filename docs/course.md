# Курс (П3)

Из учебного слоя главы (`layer.json`) собирается **офлайн-сайт**: путь по главе, страницы шагов с заданиями и иллюстрациями, карточки, конспект, карта связей. Сервер, логин и интернет не нужны.

## Как открыть
Двойной клик по `out/<ch>/course/index.html`. Вся папка `out/<ch>/course/` самодостаточна (CSS, JS, KaTeX, иконки, иллюстрации, сканы страниц лежат внутри). Её можно скопировать или заархивировать целиком. Размер у Барабошкина (6 шагов, 7 иллюстраций, без сканов и видео) — 2 МБ, лимит ≤ 30 МБ на главу без видео.

## Как собрать
```
make course CH=<id> [NODE=<id узла>] [NO_LLM=1] [DOMAIN=<домен>]
make illus  CH=<id> [NO_LLM=1] [DOMAIN=<домен>]            # иллюстрации; make course сам их не строит
python -m pipeline.course.build --ch <id> [--node <id>] [--no-llm] [--domain <д>] [--out out/] [--pages data/pages/]
python -m pipeline.illus.run    --ch <id> [--no-llm] [--domain <д>] [--styleguide <файл>]
```
- `NO_LLM=1` / `--no-llm` — модель не вызывается: берутся уже сохранённые `step_text.json`, `tasks.json`, `interactive.json`, `guesses.json`; чего нет — собирается из полей слоя (запасной вариант) с предупреждением.
- `NODE=…` — пересобрать один шаг; остальное берётся из сохранённого. Пересоздаются только узлы, изменившиеся по хэшу.
- Все вызовы модели идут через `pipeline/llm.py` (кэш, ключ и модель — в `.env`). `LLM_OFFLINE=1` + заполненный `cache/` — сборка без ключа.

**Вход** (`out/<ch>/`): `layer.json` — **обязателен**. Остальное по возможности, без него курс собирается беднее, но собирается:
`units.json` (домен, название главы из заголовка), `routing.json` (форматы и шаблоны), `verify/report.json` (статусы «проверено»), `illus/illustrations.json`, `videos/<узел>.short|long/` (`<id>.mp4`, `<id>.vtt`, `passport.json`; старый `videos/<узел>/` тоже находится), `data/pages/<ch>/pN.png` (сканы для окна «Проверь по книге»), лист опечаток.

## Что внутри
| Страница | Что на ней |
|---|---|
| Путь (`index`) | название главы, «N шагов · ≈ X мин · M заданий», «Начать/Продолжить» с кольцом прогресса, шаги таймлайном, части главы, фильтр «Повторить» |
| Шаг (`step-<id>`) | полоса шагов (десктоп), «Сначала угадай», «Суть», «Зачем», «Как работает», цитаты автора, формулы (KaTeX), таблицы книги, разбор примеров, «Как делает специалист», нюансы, частая ошибка, решение на данных (сигнал → правило → вывод по шагам), что значит для данных, аналогия с границей, новые понятия, иллюстрации, интерактив, ролик, задания, источник, чек-лист «шаг пройден» |
| Задания | все задания главы по шагам с состояниями |
| Прогресс | процент освоения; статусы шага: «Не начато» (ответов нет), «Нужно повторить» (есть неверные), «Закрепить» (часть верно), «Освоено» (всё верно); полоса из сегментов (пуста, пока ничего не решено), вкладки по статусам |
| Мои ошибки | неверно решённые задания, «Перечитать», «Я понял» |
| Карточки | на каждый шаг: название → «Показать суть» → «Знаю» / «Повторить» |
| Конспект | суть, формулы, графики/колонки (без схем-цепочек, они повторяют текст) и данные по шагам, кнопка «Печать / PDF»: в печати нет шапки и навигации (проверено печатью в PDF через Playwright) |
| Карта | схема опор шагов (prerequisite) и список |
| ИТ-задачи | ручные шаги, точки суждения, где ломается, аналогии (если есть в слое) |

**Фирменный знак:** логотип KERN (`assets/brand/`: `symbol.svg`, `logo.svg`, `logo-mono.svg`, `favicon.svg`) нарисован кодом из простой геометрии; в шапке слева логотип, справа название главы, favicon на каждой странице.

**Фишки:** «Проверь по книге» (окно с цитатой, статусом проверки и сканом страницы), подсветка «автор / модель / гипотеза» (кнопка «Автор / модель» в шапке; в обычном режиме у абзаца только «стр. N», плашки автора и модели видны при включённом переключателе, «гипотеза» — всегда), «Сначала угадай» (вопрос-утверждение до чтения), «Перечитать» после ошибки (скролл и подсветка абзаца с нужным утверждением), «Мои ошибки», интерактив вместо ролика: «слайдер → график» для узлов с формулой (значения считает Python, JS только рисует) и «схема-исследование» для узлов без формул (кликабельные части из утверждений узла: описание, «стр. N», «Проверь по книге», режим «проверь себя»; метка «схема»), честные пометки: «не в масштабе», происхождение кадра, «исторический прибор».

## Задания
Пять типов: `single`, `multiple`, `order` (перетаскивание за ручку пальцем или мышью + кнопки ↑↓), `gap` (слово из текста шага), `calc` (расчёт). Правила:
- Модель пишет условие, варианты и пояснение, но **числа берёт только из узла**, а **ответ `calc` считает код** (`safe_eval` по формуле главы; модель его не видит).
- Неверные варианты строятся на заблуждениях (id из доменного пакета и поле `misconception` узла).
- Каждое задание проверяется отдельно (тип, `claim_ids`, русский, длина пояснения, слово `gap` есть в тексте); слот, не прошедший проверку, перегенерируется до 3 раз, потом выбрасывается с `task_dropped`.
- **Слепая проверка ответа**: отдельный вызов модели получает только цитаты из `claim_ids`, условие и варианты без отметки верного, выбирает ответ и дословную фразу-опору. Не совпал ответ или опора не дословно из цитаты — задание перегенерируется, затем выбрасывается (`task_answer_mismatch`). Эта проверка нужна, потому что курс строится до `verify`: P2 `verify` проверяет в `tasks.json` числа, но не верность ответа.
- Минимум заданий на главу и типы задаёт план (`MIN_TASKS = 15`, ротация типов); недобор — предупреждения `few_tasks` / `missing_task_type`.

## Иллюстрации
Строятся **только кодом** по данным и формулам слоя (`pipeline/illus/`): цепочка причин, кривая, кросс-плот, колонка. Генерации изображений нет. Цвета и подписи — из `styleguide.json` (цвета легенды только внутри рисунков). У каждой метка происхождения; модель выбирает лишь параметры графика, а числа и оси рисует код. Файлы: `out/<ch>/illus/` и `illustrations.json` (схема организаторов; свои поля — в `ext["illus"]`).

## Устойчивость
- **Деградация вместо падения.** Нет `title`/`part`, нет маршрутизации, сломан один узел, модель недоступна — курс всё равно собирается: шаг строится из полей слоя, задание выбрасывается, интерактив не показывается. Причина — в `out/<ch>/course/build_report.json` (`warnings` с кодом и узлом, `summary`, `missing_scans`) и в stderr; в конце одна строка «ИТОГ СБОРКИ: текст модели: N из M шагов · заданий: K (выброшено X) · fallback: Y».
- Три отказа модели подряд или ошибка авторизации — «модель недоступна»: остальные вызовы не делаются, всё собирается из слоя.
- Повторы 429/503 и запасные модели делает `pipeline/llm.py`; для курса исчерпанные повторы — отказ узла.
- **`COURSE_WORKERS`** (по умолчанию 4) — число потоков по узлам. Выходы не зависят от числа потоков и порядка завершения. `COURSE_WORKERS=1` — последовательно.
- Правила терминов в тексте шага (≤1 выделение в «Суть», ≤2 на абзац) исполняет код, а не отказ; не выделенный термин — предупреждение `term_not_marked`.

## Контракт
- **localStorage** (префикс `course:<ch>:`): `done`, `last`, `checks`, `cards`, `tasks`, `answers`, `guess`, `understood`; общие `course:theme`, `course:by`. Формат каждого ключа описан в шапке `assets/course.js`. Если localStorage запрещён, курс работает без сохранения.
- **`ext["course"]`**: свои данные курс кладёт только сюда (`tasks.json`: `hashes`, `warnings`, `dropped`, `node_warnings`). Из чужого читает `ext["core"]` (`title`, `part`, `ocr_fixes`). Файлы `step_text.json`, `interactive.json`, `guesses.json` — внутренние кэши курса с хэшем узла.

## Ограничения и что не проверено
Только Edge (Chromium). Реальный телефон, Safari, Firefox и настоящие mp4 не проверялись; печать в PDF проверена только через Playwright (Edge), не живым диалогом печати. Порядок в задании order сохраняется после проверки ответа (так в контракте `answers`), не до неё. Главы с несколькими частями (`part`) проверены только на мини-главе. Качество текста и заданий зависит от модели: на слабой модели больше шагов уходит в запасной вариант (видно в итоговой строке).
