# Плейбук: новая глава → курс

Порядок работы на незнакомой главе: что запускать, что проверять глазами, что можно править руками и как это записать.
Команды и параметры — [docs/run.md](run.md). Здесь — последовательность и решения.

Главное правило: **учебный слой (`out/<id>/layer.json`) — единственный источник правды.** Курс, задания и ролики строятся из него. Ошибку чиним в слое и пересобираем, а не правим страницы курса.

## 0. Перед началом

1. Ключ и модель — в `.env` (раздел 2 `docs/run.md`). Проверка без ключа: `LLM_OFFLINE=1 python -m pipeline.run --smoke`.
2. Бесплатный уровень провайдера (лимиты в минуту и в день): `LLM_WORKERS=1`, `COURSE_WORKERS=1`, несколько ключей — `LLM_API_KEYS=к1,к2,…`, запасные модели — `LLM_MODEL_FALLBACK`. Платный ключ: `LLM_WORKERS=4`, `COURSE_WORKERS=4`.
3. Модель, которая сейчас перегружена (503, таймауты), лучше не ставить основной: код пережидает до 5 повторов (около 2,5 минуты) на каждый вызов, прежде чем перейти к запасной.

Ориентир по объёму (глава Барабошкина «Дельты», 15 страниц, 54 единицы, 6 узлов, Gemini Flash / Flash-Lite): ядро (рисунки, слой, маршрут) — 45 вызовов модели, ~40 минут чистого времени модели при `LLM_WORKERS=1`, 206 тыс. токенов на вход, 89 тыс. на выход, $0,42. Курс и сценарии роликов добавляют свои вызовы сверх этого.

## 1. Глава из своего домена

```
python -m pipeline.run --md <глава.md> [--pdf <глава.pdf>] [--pages a-b] [--author "…" --book "…"]
```

Экономный вариант при жёстком лимите запросов — по этапам; модель тратится только на слой и маршрут, курс собирается из полей слоя:
```
python -m pipeline.ingest.run    --md <глава.md> [--pdf …]
python -m pipeline.structure.run --ch <id>
python -m pipeline.route.run     --ch <id>
python -m pipeline.illus.run     --ch <id> --no-llm
python -m pipeline.course.build  --ch <id> --no-llm
python -m pipeline.verify.run    --ch <id>
python -m pipeline.course.build  --ch <id> --no-llm
python -m pipeline.common.metrics --ch <id>
```
Когда запросы останутся — `python -m pipeline.course.build --ch <id>` (тексты шагов пишет модель).

## 2. Глава из другого домена (сдвиг)

Движок не знает геологии: всё доменное — в пакете `domain/<домен>/`. Пакет для нового домена собирает код, не человек.

```
python -m pipeline.ingest.run --md <глава.md> [--pdf …] --domain <домен>
python -m domain.build --domain <домен> --ch <id>            # время сборки — в domain/<домен>/build_log.json
python -m pipeline.run --md <глава.md> [--pdf …] --domain <домен>
```
Без пакета запуск останавливается и печатает команду сборки. Существующий пакет без `--force` не перезаписывается. Пакет геологии (`domain/geology/`) на тесте не меняется.

## 3. Что проверить после прогона

| Где | Что должно быть | Если нет |
| --- | --- | --- |
| вывод `[structure]` | «цитата не подтверждена: 0»; «без узла с причиной» — только сноски, колонтитулы, повторы | утверждения с `ext.core.quote_verified: false` — исправить цитату или страницу в слое (раздел 4) |
| `out/<id>/coverage.json` | у каждой единицы — узел или причина | единица без узла с важным текстом — добавить её в `unit_ids` нужного узла |
| `out/<id>/layer.json` | у каждого утверждения страница и дословная цитата; `by_model` честный; порядок узлов без скачков (предпосылки раньше) | см. раздел 4 |
| вывод `[route]` | форматы по узлам; шортсов-крючков не больше 20% (лишние код снимает сам и пишет в лог) | формат или шаблон сцены — поле узла в `routing.json` |
| `out/<id>/verify/report.json` | нет `critical`; код выхода `verify.run` — 0 | каждое замечание — со страницей и предложенным исправлением (`fix`) |
| `out/<id>/course/index.html` | курс открывается двойным кликом; у шагов есть ссылки на страницы книги; задания решаются | пересборка курса (раздел 5) |

Что модель делает слабее всего (видно на облегчённых моделях): мало утверждений на большой узел, редко использует заблуждения из доменного пакета, ставит один и тот же тип трудности, ошибается с шаблоном сцены. Это проверять глазами в первую очередь.

## 4. Ручная правка — только через журнал

Жюри сверяет журнал с историей коммитов. Порядок:

1. Сразу после прогона закоммитить сырой результат, чтобы правка была видна отдельным коммитом:
   `git add -f out/<id>/layer.json out/<id>/coverage.json out/<id>/routing.json && git commit -m "[test] <id>: прогон 1"`
2. Поправить файл (обычно `out/<id>/layer.json`).
3. Записать правку — команда сама коммитит файл и добавляет строку в `journal/manual_edits.csv` с хэшем коммита:
   ```
   python -m journal.cli add --ch <id> --min <минуты> --what "что изменено" --files out/<id>/layer.json --reason "почему" [--people N] [--run-no N]
   ```
4. Пересобрать то, что зависит от правки (раздел 5).

Правка через ИИ-ассистента — тоже ручная правка, записывается так же. Цель — не больше 30 человеко-минут на главу.

## 5. Пересборка

| Что поменялось | Команда |
| --- | --- |
| факт в узле (число, формулировка) | `python -m pipeline.run --rebuild <id узла>` — ролик узла (если есть), затем страница шага |
| весь слой | `python -m pipeline.course.build --ch <id>` (и `pipeline.illus.run --ch <id>` для иллюстраций) |
| маршрут | `python -m pipeline.route.run --ch <id>`, затем курс |

Проверка: открыть `out/<id>/course/step-<id узла>.html` — новое число на странице; цитата автора рядом осталась как в книге.

## 6. Ролики

Нужны FFmpeg, слой и маршрут главы. Сценарий пишет модель, кадры A и B считает код, озвучка — edge-tts (наружу уходит только текст фраз).
```
python -m pipeline.video.build --ch <id> --node <id узла> [--format short|long] [--draft]
```
Ролик ложится в `out/<id>/videos/<id узла>.<short|long>/` (MP4, VTT, паспорт). После него — `python -m pipeline.course.build --ch <id>`: курс подхватывает ролик, субтитры и ссылку на паспорт. Рендер медленный: заранее проверить скорость на своей машине (`--draft`). Подробно — [docs/video.md](video.md).

## 7. Внешний пакет проверки

```
python -m pipeline.verify.external --pkg <review_package.json> --out <ответ.json> [--team <имя>]
```
Замечание выдаётся только с цитатой, найденной в главе; недоказанное — в `ext.verify.unproven`, а не ложной тревогой. Подробно — [docs/check.md](check.md).

## 8. Сдача

1. Результаты каждой главы: `git add -f out/<id>/units.json out/<id>/layer.json out/<id>/coverage.json out/<id>/routing.json out/<id>/metrics.csv out/<id>/verify out/<id>/course`.
2. Новый доменный пакет `domain/<домен>/`, журнал `journal/`, кэш `cache/llm/`, `cache/tts/`.
3. `git commit -m "[test] результаты" && git push`. Тег заморозки не переставлять.

## Если что-то пошло не так

| Сообщение | Что делать |
| --- | --- |
| `ProviderUnavailable … дневной лимит` | кончились все пары ключ × модель: добавить ключ в `LLM_API_KEYS` или модель в `LLM_MODEL_FALLBACK` и запустить ту же команду — готовые ответы берутся из `cache/llm/` |
| `… повтор N/5 через X с` | лимит в минуту или перегрузка: код ждёт сам, не прерывать |
| `LLM_OFFLINE=1, а в кэше нет ответа` | включён `LLM_OFFLINE` или кэш собран другой моделью: убрать `LLM_OFFLINE` (нужен ключ) или поставить ту модель, которой собран кэш |
| `нет доменного пакета …` | раздел 2: `python -m domain.build …` |
| `ffmpeg не найден в PATH` | установить FFmpeg и открыть новый терминал |
| `verify.run` вернул код 1 | в `out/<id>/verify/report.json` есть `critical`: исправить в слое через журнал, пересобрать |
