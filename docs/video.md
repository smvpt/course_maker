## Hello-ролик 9:16

```powershell
.venv\Scripts\python -m pipeline.video.build --ch video_hello --node video_hello.pipeline_check `
    --script fixtures/video/hello/script.json --scene-spec fixtures/video/hello/scene_spec.json --draft
```

Без `--draft` рендер идёт в 1080×1920 @ 30 к/с, с `--draft` — в 540×960 @ 15 к/с. Голос задаёт `--voice` (по умолчанию `ru-RU-DmitryNeural`), он один на всю серию. `TTS_OFFLINE=1` собирает ролик только из кэша.

Выходы лежат в `out/<ch>/videos/<video_id>/`:

| Файл | Что это |
|---|---|
| `<video_id>.mp4` | H.264 High, yuv420p, AAC 48 кГц, громкость −16 LUFS (loudnorm в два прохода), истинный пик ≤ −1 dBTP |
| `<video_id>.vtt` | полный текст фраз; строка `NOTE` указывает, из каких меток взяты интервалы |
| `timeline.json` | начало и конец каждой фразы, паузы, метки слов в секундах ролика |
| `build_report.json` | версии, параметры, замер громкости, ffprobe и результаты проверок |
| `script.json`, `scene_spec.json` | вход, по которому собран ролик |
| `_work/` | промежуточные файлы: `speech.wav`, рендер Manim |

## Как устроено

1. Каждая фраза озвучивается отдельно через edge-tts (`tts.py`) с кэшем в `cache/tts/`. Сервис периодами рвёт соединение без аудио (`NoAudioReceived`), поэтому стоят повторы через 2, 5, 10 и 20 с. Если все попытки неудачны, сборка падает с понятной ошибкой. Голос сам не подменяется.
2. Аудио декодируется в PCM 24 кГц. Таймлайн (`timeline.py`) строится по числу сэмплов: вступление 0.3 с, фраза, `pause_after_s`, …, пауза после последней фразы, хвост 1.0 с.
3. Субтитры берутся из меток edge-tts. Если метки пословные (`WordBoundary`), длинная фраза режется на реплики до 42 символов. Если метки по предложениям, реплика равна предложению и до слов не дробится. Если меток нет или они не сопоставились с текстом, реплика равна фразе по границам её аудио. Источник меток записан в `NOTE` VTT и в `timeline.json`.
4. Сцена (`scene_hello.py`): всем кадром управляет одна переменная — время t. Подписи (`on_screen`) и полоса хода озвучки берут границы из таймлайна, поэтому длительность анимации задаёт фактическая длительность звука. Число кадров считается явно: ровно `round(total × fps)`.
5. Компоновка (`layout.py`) задана в пикселях опорного кадра 1080×1920. Безопасная зона и минимальный кегль подписи берутся из `styleguide.json`. Элемент за пределами зоны или кегль меньше 44 px — ошибка сборки.
6. ffmpeg: видео дотягивается последним кадром до длины дорожки, звук нормализуется к −16 LUFS, итог обрезается по длине дорожки. Последняя фраза поэтому не режется. После сборки ffprobe, ebur128 и silencedetect проверяют кодек, размер, длительности дорожек, громкость и тишину в конце. Любое несоответствие — ошибка.

## Сценарий и спецификация сцены из слоя (`video.spec`)

```powershell
.venv\Scripts\python -m pipeline.video.spec --ch <id> --node <node_id> [--layer <layer.json>] [--routing <routing.json>]
```

Вход по умолчанию — `out/<ch>/layer.json` и `out/<ch>/routing.json`; для тестовых данных пути задаются явно. Список глав и `config/chapters.yaml` не используются. Выход — `out/<ch>/videos/<node_id>.<short|long>/script.json` и `scene_spec.json`. На этом этапе нет ни озвучки, ни рендера.

1. **Узел и маршрут.** `layer.chapter` и `routing.chapter` должны совпадать с `--ch`. Узел должен быть в слое, у него ровно один маршрут, а сам маршрут — видео: `шортс` или `длинное видео` в `format` либо в `secondary_format`. Шаблон T1–T4 берётся из `template` маршрута. Любое несоответствие — ошибка с кодом выхода 2.
2. **Сценарий.** Вызывается `pipeline.llm.complete_json` с промптом `prompts/video/script.md` (уровень модели `strong`); ответ — `ScriptDraft`, то есть поля `Script`, которые пишет модель. `video_id`, узел и формат проставляет код.
3. **Спецификация сцены.** Промпт `prompts/video/scene_spec.md` (уровень `default`), ответ — `SceneDraft`. Шаблон проставляет код из маршрута.
4. **Проверка кодом** (`spec_check.py`).
   - Сценарий: первая фраза — hook; порядок problem → solution → naming и data → decision → transfer; после transfer только final; есть prediction с вопросом и паузой 1,0–1,5 с, за ним следует ответ; фразы не длиннее 18 слов, в речи нет цифр; подписи не длиннее 8 слов, без формул, «=» и греческих букв, цифры в подписях — только из текста и цитаты утверждения, указанного в `claim_id` этой фразы (id, ссылки и номера страниц источником чисел не считаются); у каждой фразы `claim_id` из этого узла; аналогия названа аналогией; оценочная длительность — 40–75 с для short и 90–180 с для long.
   - Сцена: каждая фраза ровно в одном кадре, пустых кадров нет, кадры идут в порядке фраз; допустимые метки по классам — A: «симуляция», B: «симуляция» или «схема», D: «схема». C и «реальные данные» запрещены, пока не подключён датасет. Плашка начинается с «не в масштабе» и содержит число; каждое преувеличение — с числом; при наличии преувеличений обязателен `true_scale_shot_id`, и этот кадр без плашки; `objects`, `invariants`, `assumptions` и `params` не пустые.
   - Если есть замечания, делается одна повторная попытка: их текст передаётся модели в переменной `feedback`. Если и она не прошла — ошибка, файлы не пишутся.
5. **Что дописывает код.**
   - `scene_spec.ext.video.sources` — таблица «claim_id → стр. N + дословная цитата на языке оригинала». Она строится из claims узла, а не из ответа модели.
   - `script.ext.video.duration_estimate` — **оценка** до синтеза: слова при 130 слов/мин плюс паузы, с пометкой «не замер».
   - `ext.video.route` — данные маршрута; `ext.video.source_language` — язык цитат узла.
6. **Если нет `pipeline.llm`** (ядро П1 не влито), выдаётся понятная ошибка. Фиктивной генерации нет.

## Тесты

```powershell
.venv\Scripts\python -m pytest tests/video -q
```

Тесты работают без сети, сервис edge-tts в них подменён. Они проверяют таймлайн из нескольких фраз с паузами, интервалы VTT, кэш TTS (попадание, промах при смене текста или любого параметра, `TTS_OFFLINE`, оборванная запись), ошибки входа и CLI.

Для `video.spec` подменяется `pipeline.llm`: подставной модуль с тем же интерфейсом `complete_json`, который вдобавок сверяет переданные переменные с плейсхолдерами файла промпта. Ответы модели лежат в `fixtures/video/spec/llm_*.json`. Тесты проверяют успешную генерацию, второй формат маршрута, английские цитаты, неизвестный узел, чужую главу, маршрут не на видео и отсутствие маршрута, чужой `claim_id` (с повторной попыткой), исправление ошибки на повторе, нарушенные связи кадров, ошибку JSON от ядра и отсутствие `pipeline.llm`. Все правила `spec_check` покрыты отдельными тестами.
