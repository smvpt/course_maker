# П2 — модуль проверки и доменный пакет (роль в команде: геология)

Сначала прочитай корневой `CLAUDE.md` — там границы и интерфейсы. Твоя зона там же, строка «Проверка».
Ты отвечаешь за точность: без тебя команду не допустят, а за закладки дают 10 баллов и стажировку.

## Баллы, за которые ты отвечаешь
Проверка на закладках (10) + сдвиг (5: доменный пакет и время) + допуск (у утверждений есть страницы, нет критических ошибок) + ручной труд (10: журнал).

## Что тебе нужно от других и где взять
- Формат узлов, замечаний, сцен — `contracts/models.py`.
- Пример слоя — `fixtures/core/mini_chapter/` (до его появления — сделай свой мини-слой в `fixtures/verify/`).
- Тексты книг с метками страниц — `data/books/*.md`. Можешь начинать сразу, ни от кого не завися.

## Форматы организаторов (обязательно, см. `CLAUDE.md` §1б и `data/organizers/02_модуль_проверки/README.md`)
- Вход `external.py` — `ReviewPackage` (`review_package.schema.json`): `items` типов `claim` (страница + цитата), `analogy` (с `breaks_where`), `script_line` (таймкод + `claim_ref`), `scene_fact` (`spec_path`), плюс `scenes` (полные спецификации) и `frames` (PNG-кадры с классом, меткой, `shows`, `plaque`). Кадры смотри vision-моделью: глубина вверх, газ под нефтью, неверная метка, неподписанное преувеличение → `frame_error`.
- Выход — `ReviewOutput` (`review_output.schema.json`): ОДНО замечание на цель (засчитывается первое), `category` — коды организаторов (`overgeneralization`, `sign_flip`, `measured_vs_inferred`, `lost_condition`, `missing_caveat`, `wrong_scaling`, `wrong_mechanism`, `outdated_as_current`, `analogy_without_limit`, `frame_error`, `other`), `severity`, `problem`, `fix` (непустой!), `page_pdf` (для кадров и фактов сцены — страница утверждения, которое иллюстрирует ролик).
- Полный балл = верная цель + непустой `fix` + страница из ключа; половина — без исправления или страница не та; замечание к верному элементу — ложная тревога (в пакете есть «верные, но неожиданные» элементы).
- `eval.py` = запуск скрипта организаторов: `python data/organizers/02_модуль_проверки/score_review.py <ответ.json> <key.json>`. Контрольный пакет — `02_модуль_проверки/контрольный_пакет/` (глава Вендельштейна, 90 целей, около пятой части с ошибками). **Ключ `key.json` не открывать до первого прогона** — ни тебе, ни агенту. Тестовый пакет выдадут после заморозки без ключа.
- Журнал — `journal/manual_edits.csv` с колонками организаторов: `time, chapter, file, what_changed, person_minutes, people, run_no, reason`. Пишется ЛЮБАЯ правка результата после сырого прогона, включая правки через ИИ-ассистента. Минуты менторов — в `metrics.csv` (колонка `mentor_minutes`, П1 собирает), поэтому `journal/cli.py` умеет `add-mentor --ch --min`, которое пишет в `journal/mentor_minutes.csv`.
- Доменный пакет — структура `05_шаблоны/domain_pack_template.md`; заготовки — `04_доменные_заготовки/` (`misconceptions.json`, `physics_checklist.json`, словарь ударений и произношений) и `03_стайлгайд/styleguide.json`. Для сдвига оценивается: пакет отделён от кода, записано время сборки и какие шаблоны сцен подошли без изменений.

## Задачи по порядку

### 1. Детерминированные проверки — до 18:00
- `pipeline/verify/pages.py`: индекс «страница → текст» по меткам `<!-- page N -->`; нормализация (переносы «-\n», ё→е, кавычки, пробелы, LaTeX-мусор, латиница вместо кириллицы в OCR).
- `quotes.py`: цитата на указанной странице или ±1 (rapidfuzz `partial_ratio`, порог подбери на тестах) → `found | other_page(N) | not_found`. Экспортируй функцию `check_quote(chapter_id, page, quote)` — её вызывает П1 в цикле структурирования.
- `numbers.py`: все числа из текста узла, курса, сценария (десятичная запятая, диапазоны «5–20», степени `10⁻²`, проценты) → есть ли в исходных единицах узла. Числа словами в сценарии — нормализуй обратно.
- `terms.py`: термин глоссария не встречается в тексте узлов раньше узла, где он определён.
- `run.py --ch`: всё это по `layer.json` (+ курс П3 и сценарии П4, если есть) → `out/<ch>/verify/report.json` в том же формате `ReviewOutput`, что и ответ на внешний пакет (`package_id` = id главы, `target` = id утверждения/фразы/кадра) — один формат замечаний на всё. Код выхода ≠0, если есть `critical`.
- Тесты: найденная цитата с OCR-опечаткой; выдуманная цитата; число из воздуха; цитата со соседней страницы.

### 2. Проверка сцен — до 21:00 (П4 сдаёт спецификации менторам к 22:00)
`scene.py`: `SceneSpec` + `Script` против обязательных пунктов честности (есть `true_scale_shot_id`, у каждого преувеличения число, у каждого кадра класс и метка, у каждой фразы `claim_id`, аналогии помечены) и против чек-листа физики из доменного пакета: глубина вниз, газ > нефть > вода, порядок слоёв, причина раньше следствия, правдоподобные числа, преувеличения названы числом, класс A/B не помечен как генерация, нет фраз из списка заблуждений. Плюс числа и `claim_ids` сценария через `numbers.py`.

### 3. LLM-критик и внешний пакет — до 02:00
- `critic.py`: для каждого утверждения — его страница → strong-модель с JSON-ответом `{verdict: supported|contradicted|not_in_source, category (коды организаторов), severity, problem, fix, page_pdf, quote}`. Отдельные инструкции по категориям закладок: сверхобобщение, переворот знака, измеренное вместо выведенного, потеря условия, пропуск оговорки, неверный закон масштаба, неверный механизм, устаревшее как текущее, ИТ-аналогия без границы, ошибки кадров.
- Ошибку выдаём ТОЛЬКО при `contradicted` + `quote`, найденной `quotes.py` на странице `page_pdf`. Неожиданное, но подтверждённое — не трогать (ложная тревога = минус).
- `external.py --pkg --out`: принимает чужой пакет (утверждения, сценарии, спецификации, кадры), прогоняет всё выше, выдаёт замечания с исправлением и страницей. Формат входа — по формату организаторов; пока его нет — по нашим контрактам, с адаптером в `external.py`.
- `eval.py`: сравнение с ключом контрольного пакета закладок → recall, ложные тревоги. Если пакета ещё нет — сделай свой: испорть ~20% верных утверждений из слоя по категориям и проверь.
- Цель: ≥70% найдено, ≤2 ложные тревоги. Крути промпты и пороги ДО заморозки.

### 4. Доменные пакеты
- `domain/geology/`: структура строго по `05_шаблоны/domain_pack_template.md`: `glossary.md` (RU/EN, определение, западный аналог), `misconceptions.json` (взять файл организаторов, id `misc.*`, дополнить), `physics_checklist.json` (взять файл организаторов, id `pc.*`), `it_bridges.md`, `styleguide.json` (копия файла организаторов), `pronunciation.md` и `stress_dictionary.md` (из заготовки организаторов «словарь ударений и произношений»), `errata/` (листы опечаток по главам), `templates/` (параметры шаблонов сцен по типам трудности — пишет П4). Вики по корпусу от организаторов — второй источник для критика, не готовый ответ.
- `domain/build.py --domain <name> --ch <id>`: собирает такой же пакет для нового домена из главы + общего шаблона + LLM. Прогони на бурении заранее (раздел чек-листа «Бурение и скважина» уже есть в ТЗ), замерь время. На тесте этот скрипт соберёт пакет для сдвига.

### 4б. Паспорт доверия (до 06:00)
`verify.run` дополнительно пишет `out/<ch>/verify/trust.json`: покрытие единиц %, цитат сверено %, чисел сверено %, замечаний по уровням, ручные минуты по журналу, стоимость из `out/_metrics/llm_calls.jsonl`. П3 показывает это страницей курса.

### 5. Журнал
`journal/cli.py add --ch --min --what [--files]`: дописывает `journal/manual_edits.csv` (формат организаторов, `ManualEdit`), делает `git commit` с этими файлами и пишет хэш в запись. `journal/cli.py report` — минуты по главам.  Журнал обязан совпадать с историей коммитов — каждая ручная правка результата делается ТОЛЬКО через эту команду.

## Контрольные точки
- 18:00 — цитаты/числа/термины в main, П1 вызывает их.
- 21:00 — `scene.py` готов для спецификаций П4.
- 02:00 — критик + external + eval, первые цифры recall/ложных тревог.
- 08:30 — прогон на контрольных главах, пакет бурения собирается скриптом.

## Нельзя
Менять чужие зоны; «чинить» слой или курс самому — ты только выдаёшь замечания; флагать без доказательства.
