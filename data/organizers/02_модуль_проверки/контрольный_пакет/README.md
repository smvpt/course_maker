# Контрольный пакет ctrl_vendelshtein

Черновик учебного материала по главе Вендельштейна (оценка коллекторов и насыщения по данным ГИС). В нём есть ошибки, которые заложены заранее. Ваш модуль проверки должен их найти, указать исправление и страницу главы, которая это исправление подтверждает.

## Что в пакете

| Файл | Что это |
|---|---|
| `package.json` | Пакет по схеме `review_package.schema.json` |
| `frames/F01.png … F09.png` | 9 кадров ролика `ven_v1` (про ложный ВНК). Метаданные кадров лежат в `package.json → frames` |
| `key.json` | Ключ с ошибками и «верными, но неожиданными» элементами. **Не открывайте его до прогона** |

Глава: `vendelshtein_gl1.md` (стр. PDF 9–14 и 20–30, номера страниц заданы метками `<!-- page N -->`). Она выдаётся вместе с пакетом.

Состав: 81 элемент `items` и 9 кадров, всего 90 целей для замечаний.

- `claim`: 60 утверждений, у каждого есть страница и цитата автора (C001–C060);
- `analogy`: 5 ИТ-аналогий, у каждой указано, где аналогия перестаёт работать (A01–A05);
- `script_line`: 10 фраз закадра ролика `ven_v1`, в `claim_ref` указано утверждение, на которое опирается фраза (L01–L10);
- `scene_fact`: 6 проверяемых фактов сцены, в `spec_path` указано место в спецификации (S01–S06);
- `frames`: 9 кадров (F01–F09). У каждого кадра есть метка происхождения, описание `shows` и плашка.

Полная спецификация сцены лежит в `package.json → scenes[0].spec`.

Ошибками заражено около пятой части целей. Часть верных элементов звучит неожиданно; замечание к такому элементу считается ложной тревогой.

## Правила замечаний

- На одну ошибку пишите одно замечание и ставьте его на тот элемент или кадр, где ошибка сформулирована. Если проблема общая для всех кадров (плашка, шаблон) или касается спецификации, её проверяют через факты сцены `S…`. Если на одну цель пришло несколько замечаний, засчитывается первое.
- Исправление подтверждается страницей выданной главы. Для кадров и фактов сцены это страница утверждения, которое иллюстрирует ролик.
- Формат ответа задаёт `review_output.schema.json`: `target`, `category`, `severity`, `problem`, `fix`, `page_pdf` и, по желанию, `quote`.

## Как проверить себя

1. Прогоните модуль на `package.json` и сохраните ответ в `ответ.json`.
2. Только после этого посчитайте результат. `score_review.py` лежит на уровень выше этой папки; если запускать из папки пакета, команда такая:

```
python ../score_review.py ответ.json key.json
```

Как считаются баллы. Вес ошибки зависит от тяжести: critical = 3, significant = 2, minor = 1. Замечание засчитывается полностью, если в нём верная цель, непустой `fix` и страница из ключа. Если цель верная, но нет исправления или страница не та, замечание засчитывается наполовину. Замечание к цели без ошибки считается ложной тревогой, отдельно считаются ложные тревоги на «верных, но неожиданных» элементах.

Ключ открывайте только после прогона. Если посмотреть его раньше, контрольный пакет перестаёт что-либо проверять.
